# 【Rokid AIUI】听障助手：让听障朋友「看见」谁在说话

> 发布草稿，供粘贴到 Rokid 开发者论坛（https://developer-forum.rokid.com/）
> 发布前请替换 `[待补充]` 内容，并插入实际截图。

大家好，最近在 Rokid AIUI 上做了一个面向听障人群的智能体——**听障助手**，来论坛分享下思路和踩过的坑。

## 为什么要做这个

听障朋友在面对面交流时，最大的困难不是「完全听不见」，而是两件事叠加：

1. 听不清对方在说什么；
2. 在多人场合里，分不清**到底是谁在说**。

市面上不少转写工具只能解决第 1 点。但如果你不知道这句话是谁说的，字幕的价值会大打折扣——尤其是一家人围坐聊天的时候。

所以听障助手的核心目标是：**不只转写内容，还要标出说话人**。

## 四个功能

按顺序用效果最好：

1. **录入声纹**（首次必做）
   按屏幕提示朗读，录满 **3 句以上** 就建立这个人的声纹。建议给家人、同事各录一次。

2. **验证身份**
   说一句话，系统判断「现在说话的是谁」，给出最匹配身份和相似度。

3. **对话字幕**（核心）
   实时把对方的话变成字幕显示在眼镜上，格式是 `说话人：内容`：
   - 已录入的人 → 直接显示**姓名**
   - 没录入的人 → 显示「陌生人N」，**短按就能现场起名**，起完名自动入库，以后再说话就认得他了

4. **拍摄解说**
   拍下眼前画面，由视觉模型生成解说并语音播报（需要配置 API Key，没配置时是演示模式）。

## 技术实现要点

- **声纹引擎**：自己实现的特征提取（能量 / 谱质心 / 过零率 / 谱通量 / MFCC 近似），模板比对用 MFCC 余弦相似度 + 标量高斯相似度的加权。全部数据存设备本地 storage，**不上传服务器**。
- **语音转文字**：直接用了 Rokid 的能力 `wx.getSpeechRecognizer()`——这是 AIUI 的 Rokid 特有能力，通过 `onRecognize` / `onStop` 回调拿 `res.result`，比自己接云端 ASR 省事很多。
- **语音播报**：用了 `wx.getSpeechSynthesizer()`，在关键状态和**报错、卡死**时语音提示，让用户可以不一直盯着屏幕。
- **无障碍**：大字体、高对比（黑底绿字），振动 + 语音双反馈。

## 踩过的坑（重点）

1. **`.ink` 模板指令要用 `ink:` 不是 `wx:`**
   依据官方 aiui-dev skill 和 examples，标准前缀是 `ink:if` / `ink:for` / `ink:key`。我早期误改成 `wx:`，后来全量改回来了。

2. **`.aix` 是 zip 产物，改完代码必须重新打包**
   有次提交忘了重打包，导入运行直接缺页面、缺 utils。现在养成习惯：
   ```bash
   zip -r aiui-voiceprint.aix app.json app.js package.json AGENTS.md README.md pages utils -x '*.DS_Store' '*.aix'
   ```

3. **录音卡死 / 退不出来**
   原因很隐蔽：`recorderManager.start()` 如果抛错，排在它**后面**的「3 秒后自动停止」定时器就永远排不上，状态卡在「开始录音」不动。
   解法：定时器**先排**，`start()` 用 `try/catch` 包住；`stop()` 也包 `try/catch`，保证后续处理一定执行；再加卡死看门狗。

4. **真机镜腿手势的两个坑**
   - 用户实测**滑动反馈不可靠**（"无法滑动"）；
   - 一次物理按压可能被上报成**多次 keyup**，导致单击被误判成双击，进而误触发退出。
   解法：加按键去抖（150ms 内重复上报忽略），并把关键操作改为**短按 / 双击**驱动，不依赖滑动。

5. **审核被驳回过**
   驳回意见是「功能介绍要加强用户引导」+「Studio 里要加预览图」。
   整改：主页加了「首次使用引导」三步卡片，README/AGENTS 改成按使用顺序的引导式介绍，另做了 3 张预览图（功能总览 / 手势指引 / 字幕场景）传到 Studio。**预览图这步只能人工在 Studio 后台传**，代码里没法代传。

## 怎么体验

两种都行：
- 在 Rokid AIUI Studio 里**导入** `aiui-voiceprint.aix`；
- 或用 Studio **直接打开项目目录**（入口 `app.json`）。

## 最后

做下来最大的感受是：**听障辅助类产品，「谁在说」和「说了什么」同样重要**。声纹 + ASR 的组合在眼镜这个形态上很自然，Rokid 把 ASR/TTS 都做成可直接调用的 `wx` 能力，开发体验是顺的。

也欢迎做无障碍 / 声纹 / 语音方向的朋友一起交流，特别是**真机镜腿滑动手势**这块，如果你有更可靠的做法，非常想请教。
