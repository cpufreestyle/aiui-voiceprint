Ground Truth · 壹

核心真相：Rokid 不开放自定义热词

「听障助手」不能被注册成独立热词直接唤醒。系统唤醒词固定为「Hi Rokid」（或长按触控板），第三方无法注册热词——这是本方案一切设计的前提，不是待优化项，是平台硬边界。

Platform Constraint

本方案的「热唤醒」= 系统唤醒词 + 语义意图路由 + 应用内参数分发，三层拼出来的等效体验，不是真正意义上的自定义热词。

app.json 也没有 intent/skill 字段可供声明语音意图——只有 pages / window / permissions。因此意图声明全部落在 AGENTS.md（OS/LLM 路由依据），运行时参数走 onLaunch(options) / onShow(options)。两头都要做，且应用内必须能从原始 query 文本自行解析，因为 OS 能否把「模式」作为结构化参数传进来本身是未决项（见 §未决项 1）。

LAYER 01 · 系统侧不可改

Hi Rokid 唤醒词

固定唤醒词，第三方无法注册热词，也无法自定义触发短语。

LAYER 02 · 应用可控

AGENTS.md 语义路由

AIUI OS 依据 AGENTS.md 的技能描述做语义匹配，触发说法即 few-shot 例句，需穷举口语变体。

LAYER 03 · 应用可控

onLaunch 参数分发

options 多字段名容错解析 + intent-router 从原始文本兜底解析模式，不依赖 OS 精确传参。

Capability Chains · 肆

三条能力链：路由 · 图形识别 · 拍照生成发手机

壹

用例 A · 热唤醒与意图路由

Hi Rokid 唤醒 → AIUI OS 语义路由 → onLaunch 分发 → intent-router 两级匹配。

  • AGENTS.md 全部重写：现有版本是英文脚手架残留，路由匹配价值≈0；需中文身份+System Prompt+三技能触发说法穷举——路由是 LLM 语义匹配，例句就是它的 few-shot。
  • app.js 多字段名容错：官方文档未明确 query 载荷键名，query/text/utterance/asr 全候选都摸一遍；OS 若真能传结构化 mode 则最高优先，否则从原始文本解析。
  • intent-router 两级：正则秒判（0 成本、离线可用，顺序即优先级）→ session.prompt() 轻量 LLM 兜底，仅置信度低时调用，失败静默落 home。
  • 路由表与 AGENTS.md 触发说法必须同步维护，否则出现「OS 路由进来了、应用内认不出」的割裂。
// utils/intent-router.js 一级规则表节选 { mode:'genimg', re:/(生成|画).{0,8}(相似|类似|模型)|发(到|给).{0,4}(手机|电话)/ } { mode:'shape', re:/(拍照|拍一?张|看看).{0,10}(识别|是什么|图形|形状)/ } { mode:'caption',re:/(字幕|转写|说什么|对话|听不清|实时)/ }

用例 B · 拍照识别图形

零新文件——vision.js 加一个定制 prompt 的入口 + media 页加 shape 模式分支，链路完全复用既有解说通道。

  • prompt 参数化，不复制逻辑：describeImage 内部固定 prompt 抽成参数，内部函数 callVisionGateway({imageDataUrl, prompt})；describeImage 与 describeShape 都是它的薄封装，请求/降级逻辑只有一份。
  • 结构化输出 7 段：类别 / 形状构成 / 尺寸比例 / 颜色 / 文字 / 空间关系 / 可能用途，总长 ≤300 字，适合语音播报；【】分段直接按行拆开渲染成分节字幕，可读性优于整段。
  • media 页 mode==='shape' 时标题/按钮文案切换，autoStart==='1' 时 onReady 后直接触发拍照，跳过手动按钮。
  • 降级保留：apiKey 未配置 / 断网 → 返回既有固定演示文案，流程不中断。
// utils/vision.js 新增导出（节选） var SHAPE_PROMPT = '你是视觉结构分析助手...严格按以下结构输出：\n' + '【类别】【形状构成】【尺寸比例】【颜色】【文字】【空间关系】【可能用途】' export function describeShape(dataUrl) { return callVisionGateway({ imageDataUrl: dataUrl, prompt: SHAPE_PROMPT }) }

用例 C · 拍照 → 生成相似图 → 发到手机

诚实边界先立：眼镜端只做「拍照 + 两次 wx.request + 显示取件码」；图像生成与送达手机全靠外部组件（②③ 号必须新建，非眼镜端代码）。

  • imagegen.js：POST 图生图，优先要求服务端返 URL 而非 b64（relay 只中转 URL，避免眼镜端二次搬运大体积 b64）；降级为 {imageUrl:'', demo:true} 演示文案。
  • phone-bridge.js：makeCode 生成 4 位取件码（语音可播报）→ pushResult 把 code+imageUrl POST 给 relay → qrDataUrl 三级降级（内置纯 JS 二维码库 → relay 代画 /qr → 只显示大号取件码+TTS 逐位播报）。
  • genimg 页：autoStart 拍照 → 字幕「生成中…」（生成 API 通常 5–30s，须有进度提示与超时兜底）→ 渲染二维码/取件码 + TTS「已生成相似图，手机扫码或输入取件码查看」。
接口说明
POST /push{code, imageUrl, ttlSec} → {pullUrl}，内存/Redis 存储，TTL 过期即焚
GET /pull?code=1234 → {imageUrl} | 取件码不存在或已过期
GET /r/{code}手机 H5 结果页，服务端渲染 <img>+长按保存提示，零安装
GET /qr可选：服务端生成指向 /r/{code} 的二维码 PNG
安全底线：code 4 位 + 30 分钟 TTL + 单 code 限拉 N 次防遍历；relay 不存任何用户身份，仅做匿名短时中转。
实现时二选一定死：若所选生成 API 只回 base64，需由 relay 落地成 URL（眼镜端把 b64 POST 给 relay，relay 存文件返回 URL）——这会把 relay 契约从「只存 URL」升级为「可存图」，两种契约不能都留着，立项时必须定死一种。

Open Risks · 柒

风险与未决项 · 8 条

需向 Rokid 官方或实机确认；本方案已按最坏情形设计，若平台能力实际更强，对应模块可退化为校验层，白赚精度。

01

语义路由粒度

智能体商店路由能否做到「带参数唤起指定模式」（把 mode=shape 结构化传入），还是只能唤起 Agent 并透传原始话语？——本方案按后者（最坏情形）设计，若前者可行则 intent-router 退化为校验层，白赚精度。

验证法：发一版含重写 AGENTS.md 的测试包，实机说三类指令，log 打印完整 onLaunch options JSON。

02

options.query 真实字段名与结构

query 是 string 还是 object？键名是 query/text/utterance 中哪个？onShow 热启动时是否重复携带？——app.js 已做多候选容错，但需实机 log 定死后删冗余分支。

03

redirectTo 在 onLaunch 时序

onLaunch 内立即跳页在该 QuickJS 运行时是否稳定（本方案已用 setTimeout(0) + globalData 双保险，需实测是否够）。

04

路由匹配率与技能描述迭代

AGENTS.md 触发说法覆盖不足会导致「Hi Rokid 听懂了但没派给我们」；上架后需按真实 miss 语料迭代描述，确认商店更新 AGENTS.md 是否需重新审核、生效周期多长。

05

图像生成供应商与成本

Agnes 网关是否开放 OpenAI 兼容的 images 图生图端点未证实；若否需另选供应商。单张生成成本 × 预期调用量，以及生成内容合规责任（用户拍到人脸/敏感物再生成的合规边界）需立项前定。

06

relay 合规与运维

中转图片即使短 TTL 也属用户内容存储，需明确隐私声明、部署地域、HTTPS 证书与限流；4 位取件码的防遍历参数（TTL/次数）要压测定值。

07

wx image 组件加载外网图片

relay 代画二维码方案依赖端上 <image> 能加载 https 网络图，需实机验证；不行则直接走取件码兜底。

08

session.prompt() 可用性与延迟

端上 LLM 在本机型的注入情况、首 token 延迟——决定二级路由兜底是否值得保留。

路由质量 = AGENTS.md 写得好不好 + 应用内兜底解析强不强。两头都要做，不依赖 OS 精确传参——这是本方案在「无自定义热词」这一平台硬边界下，能拿到的最诚实的等效体验。
