# 开发记录：官方审核整改（手势区分 + 录音链路）

> 日期：2026-09-26 ｜ 对应轮次：第 4 轮续作（收尾）

## 一、官方驳回理由

1. **录入功能不可用**
2. **由于滑动和点击事件没有区分开，所以无法体验其他内容**

## 二、根因分析

### 驳回理由 1：录入功能不可用

```
recording-session.js 给 recorder.start() 多传了 duration + encodeBitRate
  → wx.media.getRecorderManager().start() 官方签名只接受 4 参
    （sampleRate / numberOfChannels / format / frameSize）
  → start() 抛错（Promise reject）且未被 catch
  → 录音从未真正开始
  → 3s 后 _autoStop 合并 0 帧
  → isRecordingValid(combinedAudio) === false
  → wizardRetry() 无限重录循环
  → 审核者看到「总是马上失败重来」= 录入功能不可用
```

官方文档依据（已抓取存档）：
- `wx.media.getRecorderManager()` 的 `start()` 只接受 4 参，返回 Promise（拒绝时 reject）
- `onFrameRecorded({frameBuffer, isLastFrame})`：frameBuffer 只在回调内有效，**必须 .slice(0) 复制**
- `onStop` 才是可靠完成信号；`onError({errMsg})` / `onStart` / `onInterruptionBegin|End` 均存在

### 驳回理由 2：滑动和点击没有区分开

```
gesture.js parseKeyEvent 兜底把未识别 code 当 tap
  + DOM 层零手势识别（拖拽结束会被浏览器/运行时合成为 click）
  → 审核者（AIUI Studio 预览是 Web 端，鼠标/触屏操作）
  → 一拖拽切换功能 = 同时触发 swipe + tap → 立刻进入页面
  → 「想滑到其他功能，却每次都直接进了当前功能」= 无法体验其他内容
```

## 三、修复方案

### 3.1 录音链路（对应驳回理由 1）

| 文件 | 修改 |
| --- | --- |
| `utils/recording-session.js` | `start()` 只传 4 参；`onFrameRecorded` 帧 .slice(0) 复制后存 `page._frameBuffers`（**不再镜像进 page.data**——data 必须 JSON 可序列化，ArrayBuffer 进去会让 setData 报错或变 `{}`）；`onStop` 事件驱动收尾（graceMs=0）+ 1500ms 兜底；`_stopFinalized` 幂等；`onCombined(audio, meta={reason,frames,error})`；新增 `teardownRecorderListeners` / `abortRecordingSession` |
| `pages/enroll/enroll.ink` | `onCombined(combinedAudio, meta)`：`frameCount = meta.frames ?? length`；链路失败（meta.error 或 0 帧）累计 `_recFailStreak >= 2` → `abortWizardWithReason()`：停向导 + 展开手动模式 + 展示 `probeRecordingApis()` 诊断 + 语音播报，**彻底断掉无限重录循环**；intro 分支 recorderManager===null 直接走诊断 |
| `pages/verify/verify.ink` | `stopVerification` 回调改 `(combinedAudio, meta)`，用 `_lastInvalidHint` 区分「无音频帧/权限被拒」与「声音太小」，提示语不再一律「请重试」 |

### 3.2 手势区分（对应驳回理由 2）

| 文件 | 修改 |
| --- | --- |
| `utils/pointer-gesture.js`（新增） | window/文档级触摸+鼠标手势识别：位移 ≥ 24px → swipe；< 24px 且 < 400ms → tap；≥ 400ms → double；**CLICK_AFTER_SWIPE_GUARD_MS=500 捕获阶段 click 守卫**：滑动后 500ms 内 stopPropagation()+preventDefault()，杜绝「拖拽结束被合成 tap」；`data-gesture-ignore` / IGNORE_CLASSES / `tagName===BUTTON` 只屏蔽点按不屏蔽滑动；坐标同时读 e 与 e.detail；install/remove 幂等；无 window 自动跳过 |
| `utils/tap-classify.js`（新增） | `classifyTap(ctx, {debounceMs, doubleMs})`；`POINTER_DEBOUNCE_MS=40`。**修复真 bug**：原 150ms 去抖会把「两次快速点击」当成一次 → 双击退出失效 |
| `utils/gesture.js` | 新增 `routeVoiceWakeup(ctx, event)`：`clickAiAssist`（触控唤醒）/ `乐奇` / `Hi Rokid` → tap；exit/quit/back 类 → double/back；方向词 → swipe；`parseKeyEvent` 精确匹配认 clickAiAssist 等为 tap，DOM 事件名（touchstart/mousedown…）在方向判定前返回 unknown（防 touchdown 被误判成下滑）；`safeBack(fallbackUrl, page)` 末尾兜底 `page.finish()` |
| `utils/page-shell.js` | 新增导出 `gestureVoiceWakeup(event)` → `routeVoiceWakeup(this, event)` |
| 5 个页面模板 | 全部 44 个 bindtap/bindlongpress 元素加 `data-gesture-ignore="1"`（index 12 / enroll 6 / verify 4 / conversation 10 / media 12）；`sim-tap` 视图**保留**自身 bindtap/bindlongpress **并**加 ignore（双保险）；5 页均加 `onVoiceWakeup: gestureVoiceWakeup` |
| `safeBack()` 调用点 | 全部 9 处改传页面实例，`fallbackNow()` 末尾兜底 `page.finish()`（官方页面完成 API） |

**为什么不给模板绑 bindtouch\***：window 级监听已覆盖鼠标+触屏，再绑 DOM 会与 window 监听双触发同通道、去重失效，反而把一次点击判成双击。

### 3.3 本轮续作额外发现并修复

- **`pages/verify/verify.ink` 语法错误（阻断性）**：`stopVerification` 回调残留旧签名 `(combinedAudio) => {` 与新签名 `(combinedAudio, meta) => {` 叠加成嵌套箭头函数，node --check 报 SyntaxError。若打包发布整个页面会加载失败。已删除残留行，全部 5 页 + app.js 编译校验恢复 ALL-OK。

## 五、经验

1. AIUI Studio 预览与官方审核都在 **Web 端**用鼠标/触屏操作，眼镜手势规范必须显式映射到「点按=短按、拖拽=滑动、长按=双击」，否则审核者无从体验。
2. `page.data` 必须 JSON 可序列化：ArrayBuffer 等二进制只能放 `page._xxx` 私有字段。
3. 官方 API 参数以抓取的官方文档为准，多传参数会直接 reject；Promise rejection 必须显式 catch，否则录音类功能「静默死亡」。
